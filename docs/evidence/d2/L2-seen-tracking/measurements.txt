4 · IMAGE DELIVERY — THE THREE LAYERS, CHECKED SEPARATELY; NOTHING CHANGED
────────────────────────────────────────────────────────────────────────────────────────
  (1) post-list freshness   the failing layer: fixed by PR A + this PR.
  (2) image identity        VERIFIED by reading. Every content upload gets its own path:
                            src/lib/imageUpload.ts uniqueSegment() = `${Date.now()}-${random}`
                            (profile images are the only fixed slots). A card's images come from
                            its own row or post_media_for, keyed by post_id
                            (src/lib/posts/postAttachments.ts attachmentsFor(a, postId, …)); list
                            keys are post ids. No URL is shared between posts by construction.
                            NOT MEASURED on staging data (connector down). Query owed:
                              select u, count(distinct id) from (select id, unnest(image_urls) u
                              from public.posts) s group by u having count(distinct id) > 1;
  (3) cached bytes          VERIFIED by reading. The device image cache (public/sw-image-cache.js,
                            cache "gallery-images-v3", 200 entries / 50 MB, LRU) is keyed by the
                            request URL (cache.match(request)) and stores images only — never the
                            feed's JSON, so it cannot hold a stale post list.
                            OBSERVATION, not changed here: isGalleryImage() matches Supabase
                            Storage and *.r2.dev hosts; a cdn.50mmretina.com / cdn-staging URL is
                            not matched, so those images rely on the browser's HTTP cache. That is
                            a question for OFF-4 (the plan speaks of a 300 MB device cache), not a
                            freshness fault.
                            NOT MEASURED: the CDN's Cache-Control / ETag on a real image URL
                            (needs one staging image URL; connector down) — curl -sI <url>.
