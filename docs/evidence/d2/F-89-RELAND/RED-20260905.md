# F-89 re-land · the loop, reproduced by counting mounts

**Status: WORK IN PROGRESS. This branch currently carries F-89 restored (a revert of the
revert), so its tree is byte-identical to `bf03070` — the commit that hung deployed staging.
It MUST NOT be merged in this state.** It exists so the regression can be reproduced against a
committed, re-runnable instrument before anything is changed.

## The instrument

`mountcount.prepared.mjs` counts `UI-8006 ROUTE_NOT_FOUND` console events over a fixed window and
reports a **rate**, not a total, so a slower loop cannot pass it. It also asserts the 404 actually
rendered and that no sidebars remain, so it cannot go green on a page that never drew.

Every `NotFound` mount logs that event. Under React StrictMode a healthy mount logs **twice** per
visit. The deployed regression logged roughly **twice a second**, unbounded.

`UI-8006` is untouched — not deleted, not throttled. It is the only reason this was found, and
quietening a symptom to make a page look calmer is what Standing Rule 19 forbids.

## Three things this reading establishes

**1. The earlier "the scene never rendered" was this loop, not a fixture gap.** When the in-place
scene was first run it showed the feed shell and no 404, with no console errors, and that was
reported as a scene that needed more work. It was not. `404 rendered: false` here, alongside 600
mounts, is the page never settling. **The evidence for this regression was on screen before the
Owner saw it and was misread as a scene bug.** That is a finding in its own right: the instrument
worked the first time and the operator did not.

**2. The harness reproduces it ~20x faster than the live site.** Deployed staging logged ~2/sec;
this logs 41.64/sec. The likely reason is that the live resolve path is paced by real network
latency while the fixture answers instantly, so the loop spins as fast as React will re-render.
Same defect, different clock — and it makes the harness the more sensitive instrument of the two.

**3. `asides=2` on this route.** The sidebars are present here on the broken code, which is
consistent with this being the route that actually carried the sidebar defect.

## Why every check passed before

On the catch-all route `NotFound` is a direct child of the `Outlet` and nothing above it
re-renders, so the loop does not occur. Both the developer's probe and the auditor's drove the
catch-all. This scene is that blindness closed.
