C-87 — THE CHECK ITSELF WAS THE DEFECT. Auditor's finding, accepted in full.

The first version bridged from the nav token to the id url with
[^`"'\n]{0,80} — a class that EXCLUDES BACKTICKS. In a ternary the first
branch is a template literal, so a backtick always sits between them:

    to={p?.custom_url ? `/${p.custom_url}` : `/profile/${user?.id}`}

and the pattern could never reach the fallback. Reproduced directly:

    plain   to={`/profile/${user?.id}`}                 -> matched
    ternary to={... ? `/...` : `/profile/${user?.id}`}  -> NOT matched

Every ternary fallback in the codebase was invisible. The check reported 0
while four live sites survived in src/pages/Profile.tsx. It could not have
failed on the shape that survived, which is a C-34 failure of the instrument.

THE FIX DROPS THE BRIDGE ENTIRELY: any construction of a /profile/<id>
address anywhere in src is an offender, with no navigation token required.
Ternaries, line-splits and non-link uses are all caught, because proximity
is no longer part of the rule.

C-88 — AN OPTIONAL FIELD MADE THE TYPE UNABLE TO FAIL. Same class as C-87.

C-87 was a regex that could not match the shape that survived it. This is the
same defect one level up: THE TYPE WAS THE INSTRUMENT, and declaring the field
optional is what stopped it being able to fail.

  author_handle?: string | null   on Post
      -> tsc cannot enumerate the hydration sites that lack it.
      -> PostDetail.tsx, AdComments.tsx, useAddComment.ts and three harness
         post rows were all missed. The UI gate found ONE of them, twelve
         anchors across four viewports; the rest were found only by auditing
         by hand afterwards.

  handle: string | null           required, on UserIdentityBlock
      -> removing `linkTo` was a hard error, so tsc printed the COMPLETE list
         of 30 call sites in a single run and missing one was impossible.

Same change, two shapes, one checkable. The fix is not the six hydration sites;
it is that author_handle is now REQUIRED on the harness fixture post type, so
the compiler is a check again and a new fixture post cannot silently render a
member with no reachable name.

The rule this leaves behind: when a field is added BECAUSE every carrier of an
identity must have it, optional is the wrong shape — optional says "some
carriers may omit this", which is the exact thing being ruled out.
