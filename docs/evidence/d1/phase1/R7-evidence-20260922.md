### 3.1 · The C-34 control, and one correction to it

A probe that could not have failed is not evidence. On **shape A — the real unfixed input — all
five units' probes failed before the apply**, on every object, with the reason printed per object.

On shape B, `0032`, `0034` and `0036` probes **pass** before the apply. That is the correct result:
those objects are already closed on production, so there is nothing for the probe to catch. STEP 4b
proves the apply is a genuine no-op there — ACL byte-identical before and after.

**An earlier version of the harness asserted a fail-before on *both* shapes and flagged those three
as C-34 violations.** The expectation was wrong, not the probe. Recorded rather than quietly
patched, because a harness that was corrected is the reason to trust the run that followed.

Each rollback also carries its own in-transaction post-condition that aborts the whole file if a

**Why one rollback safely serves both lane shapes** — on production it restores exactly the measured
starting ACL; on staging it restores that ACL **minus PUBLIC**, a strictly smaller privilege set
than the state being rolled back to. A rollback that under-restores is recoverable; one that
over-restores is an incident. No `_STAGING` / `_PRODUCTION` variant was needed and none was
invented (§10 reserves that to the Auditor).
