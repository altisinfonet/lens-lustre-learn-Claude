WHY THIS FILE EXISTS
--------------------
C-34, recorded against this project once already: a test that could not have been shown
failing first is not evidence. The work order §4.5 repeats it — "a probe that could not have
failed is not evidence, so each must be shown failing against the current open state before it
is accepted."

HOW IT WAS TAKEN, AND WHY IT IS NOT A DISPATCH
-----------------------------------------------
The two probes were NOT executed. §5 of the work order forbids any dispatch on either lane, and
that includes running a DO block. Instead the probes' own assertion ladder (C1 signature
resolves · C3 anon EXECUTE · C4 PUBLIC entry · C5 authenticated in the wanted direction · C6
service_role) was re-expressed as a single read-only SELECT over pg_proc/aclexplode and run
against the live staging catalogue. The SELECT reports, per signature, the FIRST assertion that
would raise.

This is weaker than running the probe in exactly one respect — it does not exercise the
plpgsql control flow — and it is equivalent in the respect that matters: it shows, from the
live catalogue, that the assertions are false today, so the probes cannot pass vacuously.
