### THE RULING — R-9, and what R-12 did with it

**The Auditor ruled option (b): a required session GUC, asserted by the operator.** BLOCKER-C is
therefore **no longer awaiting the Auditor**. It is ruled. It is *not* solved: production is still
unmeasured, which is BLOCKER-B, and this ruling does not touch it.

R-12 added an executable, fatal `DO $lane_guard$` block to **two** files — the `0027` and `0028`
rollbacks — immediately after `BEGIN;` and before the first `GRANT` of any kind. It reads
`current_setting('p32.lane', true)` and raises `P0001` unless the value is exactly `staging`.
`0038`'s rollback deliberately does **not** get the guard: its marker already handles both lanes,
and a guard there would block a legitimate production rollback.

**It is an assertion, not a detection, and that distinction is the ruling.** The file still cannot
tell which lane it is on, and R-12 forbids it from trying: `current_database()`, the pooler
username, `plpgsql_check`'s schema (itself a P33 target at ordinal `0031` — a guard reading it
would silently invert on the day that migration runs), project or host names, and `pg_authid` /
`pg_namespace` differences are all excluded. The operator asserts the lane; the file refuses
without the assertion. A wrong assertion is a wrong assertion, and the guard does not pretend
otherwise.

**The three conditions of the ruling, as implemented:**

1. **The guard is executable, fatal, and first.** Not a comment. The previous revision of both
   files carried the same constraint as prose, and Standing Rule 21 is explicit that a comment is
   not a control. Verified line-by-line: in `0027`, `BEGIN;` 108 → guard 111 → first `GRANT` 126;
   in `0028`, `BEGIN;` 98 → guard 101 → first `GRANT` 116 (which in `0028` means before both the
   `anon` grants and the `authenticated` grant on `generate_custom_url`).
2. **The file never sets `p32.lane` itself** — no `SET`, no `SET LOCAL`, no `set_config()` for it
   anywhere in either file. A file that set its own assertion would assert nothing. The only
   occurrence of the string `SET p32.lane` in the executable body is inside the error message's
   string literal, telling the operator what to do.
3. **The comparison is exact and case-sensitive.** Measured, not asserted: `'Staging'`, `'STAGING'`,
   `' staging'`, `'staging '`, `''` and unset all refuse — ten runs, five per file, in
   `R12-guard-transcript-20260922.txt`.

**The C-34 proof.** Three cases per file, in `R12-guard-transcript-20260922.txt`:

| case | `p32.lane` | SQLSTATE | message names `p32.lane` | objects changed |
|---|---|---|---|---|
| A | unset | `P0001` | yes | 0 of 11 · 0 of 5 |
| B | `'production'` | `P0001` | yes | 0 of 11 · 0 of 5 |
| C | `'staging'` | none | — | **11 of 11 · 5 of 5**, post-conditions passed |
| §4.3 | reset to unset after C | `P0001` | yes | 0 of 11 · 0 of 5 |

Case C is what makes A and B evidence. `proacl` is captured before and after each case and compared
byte-for-byte object by object, printed in full rather than summarised. Case C restores exactly
`anon` and nothing else; PUBLIC stays absent on all sixteen objects in every case.

## Not blockers — recorded so they are not rediscovered as surprises

- **`0027` retains roles by omission.** Zero `GRANT` statements; `authenticated` and `service_role`
  survive only because they hold named entries. Verified true for all 11 objects
  (2026-09-22T08:42Z), so it is safe as written — **but it is safe by the shape of today's ACL, not
  by construction.** It is the same reasoning that failed in `0029`. `0028` revokes then re-grants
  explicitly and would be self-healing. §8: recorded, not fixed.
- **The MERGED `0027` apply carries no `BEGIN;`/`COMMIT;`** while the merged `0028` apply does.
  (Both *rollbacks* have always carried one, and both now open with `BEGIN;` immediately
  followed by the R-9 guard.)
- **`0038` closes the grant, not the bug.** The hook's body still trusts a caller-supplied
  `event->>'user_id'`. The body fix is a separate unit and is out of scope (§8).
- **The `0038` marker is a comment, and Standing Rule 21 cuts both ways.** It is a *control*, not
  documentation: the rollback's branch depends on it. If it is edited away the rollback fails safe
  — leaves the grant, emits a `WARNING` — but staging then carries a named grant it did not have
  before. A drift, not a break, and announced on every run.
- **The `0038` marker had an idempotence defect, found by the fixture and fixed.** A second apply
  observed the grant it had itself added and rewrote the marker to `added=false`. The fix makes the
  first observation authoritative. Written up in `R8-evidence-20260922.md` §3.3 rather than quietly
  patched.
- **`get_public_role_user_ids` is back to its pre-#274 state** by virtue of the withdrawal, and
  Owner Decision 6 remains outstanding. Held at `0039`, prepared-only, ordinal unconsumed.
