- **`authenticated` is retained on all ten objects in `0032` and all four in `0034`**, including
  six and one respectively that have **no authenticated caller** (caller trace 2026-09-22T05:35Z).
  This unit's gate is the anonymous door; an unnecessary named grant breaks nothing, a wrongly
  removed one is an outage. Listed by name in each file's header as a candidate for a later,
  separately-gated tightening. §17: a defect outside the unit is recorded, not fixed.
- **`0036` leaves a residue on staging in both directions.** The apply ADDS a named
  `supabase_auth_admin` grant that did not exist there; the rollback deliberately does **not**
  revoke it, because on production that grant pre-exists and is GoTrue's only named path to the
  hook. Revoking it there would break password verification — the outage the apply file exists to
  avoid, caused by the file meant to undo it. The residue leaves staging marginally *more* closed
  than found, which is the acceptable direction.
- **`0036` closes the grant, not the bug.** The body still trusts a caller-supplied
  `event->>'user_id'`. The body fix is a separate unit and is out of scope here.
- **The fail-before probe correctly PASSES on fixture B for `0032`, `0034` and `0036`.** Those
  lanes are already in the target state, so the apply is a no-op — proved by STEP 4b, ACL
  byte-identical before and after. The C-34 control for those units is carried by fixture A, where
  the objects are genuinely open. An early version of the harness asserted a fail-before on *both*
  shapes; that expectation was wrong, and correcting it is recorded here rather than quietly
  patched.
