| RLS | a video is seen by its owner, an admin, or anyone the **posts RLS** lets see the ready video's post (post privacy: public / friends / private), or anyone who can see its active ad. **Member blocks are NOT applied:** `user_blocks` plays no part in `posts` RLS — staging's `can_view_post` has no `user_blocks` check (SEC-VID-6, read by SEC 2026-10-05 12:20:47Z) — so a blocked member can play a video they could already see, exactly as with photos today. If a block must stop playback, that check belongs in D2's `play-token`. **Hidden from every API role:** idempotency key, manifest hash, audio hashes, provider. No API write path except `post_videos` (own post, `video_posts` on for them) and `ad_videos`: admin INSERT / UPDATE with `video_ads` on, admin DELETE any time — one permissive policy per action since 20261005_0007 (SEC-VID-4) |

Refuses a keep below 30 days. Batches of 500 |

**Rollback:** lane-guarded; refuses while 0006 is applied (RB-PRE-002) and **while any video row exists (RB-PRE-003) — member data is never dropped**. The no-loss kill switch is VID-7's: `feature_set_mode('video_posts','off')` / `('video_ads','off')`. Only an empty unit is removed (tables included), so a re-apply starts clean.
